# PathSnap

Distributed map-matching and route reconstruction for the UE24CS352A Machine
Learning Hackathon (18 Nov 2026).

Given raw GPS traces and a per-trip road network, PathSnap scores candidate
road segments per GPS point with a scikit-learn classifier and decodes the
most consistent route with an HMM/Viterbi stage, served through a FastAPI
backend and a plain HTML/Leaflet UI.

## Setup

```bash
pip install -r requirements.txt
```

Unzip the dataset locally into `data/` (`data/train`, `data/student_test`).
Raw data and `data_cache/` outputs are never committed; cache parquet files
are regenerated by the pipeline scripts.

## Run the UI (Laptop 2)

```bash
scripts/run_ui.sh          # serves ui/ on http://localhost:5500
scripts/run_ui.sh 6000     # or pick another port
```

The UI calls the real API at `http://127.0.0.1:8000` by default. No code
change is needed for the demo; pass options in the URL:

| URL | Effect |
|---|---|
| `http://localhost:5500/?api=http://<laptop-1-ip>:8000` | Use Laptop 1's API |
| `...&trip=00000052` | Open that trip straight away (UI-03 screenshots) |
| `http://localhost:5500/?mock=1` | Offline fallback: read `ui/mock/*.json`, no backend |

When the API answers with `"mock": true` (the API-01 stub), the page shows a
MOCK DATA badge and the API's warning, so stub output is never presented as
a model prediction.

## Layout

See `docs/CONTRACT.md` for the data and API contract every module builds
against, and the sprint plan for the full repository layout.

- `src/pathsnap/` - data pipeline, HMM decoder, evaluation, API pipeline
- `training/` - harness, model scripts M1-M6, Bayesian optimisation, export
- `api/` - FastAPI backend
- `ui/` - plain HTML + JavaScript UI with vendored Leaflet
- `viz/` - EDA, Folium maps, comparison plots
- `configs/` - frozen feature column order and HMM parameters
- `results/` - run CSVs, Optuna DB, plots, maps, screenshots

## Branching

`main` is always demoable and is updated only by the release pull request
from `dev`. All work happens on `feature/`, `chore/`, `docs/` and `fix/`
branches that merge into `dev` through pull requests. Never commit `data/`,
passwords or keys.
