# DATA-04 assumptions and limitations

## What is being labelled

A `.route` file is an ordered sequence of road arc IDs, not one label for every GPS observation. These observation labels are derived estimates, not independently verified physical truth. They must be described that way in the report.

`align_route(trip)` uses Simon's current `Trip` loader and local metric projection. Its state is a position in the reference-route sequence, so repeated occurrences of an arc are distinct states. The emission cost is point-to-segment Euclidean distance in metres. A dynamic programme minimizes total distance while each step stays or advances by 1, 2 or 3 route positions. Start and end positions are free because recordings can cover only part of a reference route. Ties prefer staying. Zero-length arcs are treated as points.

This follows DATA-04 in the sprint plan. No model, candidate table or heading feature is used to construct labels. There is no ad hoc reassignment to another road when the reference is distant. Time gaps do not reset the reference alignment: a strictly monotone alignment across the full recording is required here, and its 3-position limit can be too restrictive for sparse sampling. Gap resets belong to the separate prediction decoder.

## Genuine full-dataset run

Executed on the provided 80 training and 10 student-testing trips. No evaluator data was used.

|---|---:|---:|---:|---:|
| train | 208417 | 5.6666m | 141.2730m | 23272 |
| student_test | 19160 | 5.2508m | 16.8278m | 29 |

The train tail is a real data-quality warning, not hidden or replaced. In trips 00000054 and 00000033 even unconstrained nearest-reference-segment distances have very large medians (137.75m and 121.70m respectively). These checks show a reference-coverage limitation in these trips; they do not rule out all alignment bugs or all effects of the strict transition limit. Independent review is still required. The long tail cannot be attributed solely to monotone alignment. Much of those tracks lies far from every supplied reference arc. Trip 00000002 also has a 241.31m nearest-reference 95th percentile. Evidence is in `results/labels/reference_coverage.csv`, generated by `python -m pathsnap.label_diagnostics`.

Do not present these labels as uniformly accurate. Preserve the above-50m flag for analysis. Do not silently drop those points, change the label definition or compare models on different filtered subsets. Any training exclusion policy must be agreed separately and recorded. A classifier can still be trained using the derived labels, but reported metrics measure agreement with this reference-alignment process, not verified road truth.

## Outputs and use boundary

- `data_cache/labels_train.parquet` and `labels_student_test.parquet`: exactly `trip_id, obs_idx, ref_arc, ref_dist_m`.
- Trip IDs are strings, preserving their eight-digit leading zeros.
- `results/labels/alignment_diagnostics.csv` lists per-trip residual percentiles, counts above 50m, selected start/end positions and measured runtimes.
- `results/labels/*_summary.json` contains full-split statistics.
- All 227577 observations have one label; no duplicate `(trip_id, obs_idx)` keys or null values were found.
- Do not import this module into inference. Evaluator labels must never enter prediction or the UI.
